LightGBM 原生 CUDA：构建、验证与下载

LightGBM 4.7.0.99 的非官方构建。Windows x64 用 MSVC 和 NVCC 编译单 GPU CUDA，Linux x86_64 走上游的 CUDA 路径，两边是同一份源码。

  • 4.7.0.99LightGBM 版本
  • 13.2.51CUDA Toolkit
  • 4个构建目标

先克隆

把源码连同子模块一起取下来

GitHub 自动生成的 Source code 压缩包不含完整的子模块，不能用来构建；只想用现成的 DLL 就直接去下载。

去下载

PowerShell 或 Bash，在放源码的目录

git clone --recurse-submodules https://github.com/yuweiyang9611/LightGBM-NativeCUDA.git cd LightGBM-NativeCUDA

构建目标

同一份源码，四个目标。选一个进入对应的步骤，每条命令都能直接复制。

  • Windows · MSVC 加 NVCC

    CUDA 单 GPU

    需要 Visual Studio 的 MSVC、CUDA Toolkit 13.2.51 和 CMake，产物带 sm_89 cubin 和 compute_89 PTX。

    产物Release\lib_lightgbm.dll

  • Windows · Git Bash 加 Python

    打包成 wheel

    把上一步的 DLL 装进 Python 包，需要 Git Bash 和 Python 3.10 或更新版本。

    产物dist\*-win_amd64.whl

  • Windows · MSVC

    仅 CPU

    只要 Visual Studio 或 VS Build Tools 和 CMake，不需要 GPU 和 CUDA Toolkit。

    产物Release\*.exe、*.dll

  • Linux · GCC 加 NVCC

    CUDA

    需要 GCC、CMake、CUDA Toolkit 和 NCCL，沿用上游路径，USE_NCCL 默认打开。

    产物dist/*.whl 或 lib_lightgbm.so

构建

Windows · MSVC 加 NVCC

Windows · CUDA 单 GPU

需要
Visual Studio 的 MSVC（Release 产物用 14.51 链接）、CUDA Toolkit 13.2.51、CMake
产物
仓库根目录下的 Release\lib_lightgbm.dll

PowerShell，在仓库根目录

cmake -S . -B build -A x64 ` -DUSE_CUDA=ON -DUSE_NCCL=OFF ` -DCMAKE_CUDA_ARCHITECTURES="89-real;89-virtual" cmake --build build --config Release --target _lightgbm --parallel
  • 89-real 生成 sm_89 cubin，89-virtual 保留 compute_89 PTX。要分发的构建不要写 native，它只为构建机自己的 GPU 生成代码。
  • USE_NCCL=OFF 时一次只用 gpu_device_id 选中的一张卡，num_gpu 大于 1 会直接报错。

Windows · Git Bash 加 Python

打包成 wheel

把上一步的 DLL 装进 Python 包。build-python.sh 会在仓库根目录和 Release\ 下找 lib_lightgbm.dll，在 dist\ 生成带 win_amd64 平台标签的 wheel，再安装它。

需要
Git Bash、Python 3.10 或更新版本

Git Bash，在仓库根目录

python -m pip install build wheel export LIGHTGBM_WHEEL_BUILD_TAG=1cuda132sm89ptx sh ./build-python.sh install --precompile
  • 第二行可以省略。build tag 只在 wheel 文件名里标出 CUDA 变体，不改 Python 包的版本号。

Windows · MSVC

Windows · 仅 CPU

需要
Visual Studio 或 VS Build Tools、CMake，不需要 GPU 和 CUDA Toolkit
产物
仓库根目录下的 Release\，含 .exe 和 .dll

PowerShell，在仓库根目录

cmake -B build -S . -A x64 cmake --build build --target ALL_BUILD --config Release
  • 只要 Python 包时，在 Git Bash 里运行 sh ./build-python.sh install，它会用 Visual Studio 编译 CPU 版再安装。

Linux · GCC 加 NVCC

Linux · CUDA

需要
GCC、CMake、CUDA Toolkit 和 NCCL：这条路径沿用上游，USE_NCCL 默认是 ON
产物
wheel 在 dist/ 下；只编译库时，lib_lightgbm.so 在仓库根目录

Bash，构建 wheel

sh ./build-python.sh bdist_wheel --cuda

Bash，只编译库

cmake -B build -S . -DUSE_CUDA=ON cmake --build build -j4
  • 只要 CPU 版时去掉 -DUSE_CUDA=ON。

验证

Windows · 需要一张 NVIDIA GPU

构建并跑完整测试

需要
CUDA Toolkit（nvcc 和 cuobjdump）、CMake、Python 3.11、一张 NVIDIA GPU

PowerShell，在仓库根目录

py -3.11 -m venv .venv .\.venv\Scripts\python.exe -m pip install "narwhals>=1.15" numpy scipy pytest tests/win_native_cuda_tests/run_windows_cuda_tests.ps1

脚本按 89-real;89-virtual 构建 DLL，然后检查：

  • 二进制

    用 cuobjdump 确认 DLL 里同时有 sm_89 cubin 和 relocatable PTX。

  • 训练

    真实 CUDA 训练 8 棵树：预测全是有限值，MSE 低于常数预测的一半。

  • PTX JIT

    设置 CUDA_FORCE_PTX_JIT=1 并禁用缓存，单独走一遍 PTX 路径。

  • 边界

    USE_NCCL=OFF 的构建接受 num_gpu=1，拒绝 num_gpu=2。

  • 回归

    CUDA 正确性回归：缺失值路由、直方图同步、max_depth、量化与类别分裂、bagging 和 GOSS 状态。测试说明

  • CMake 只装在 CLion 里时，加 -CMakeExecutable 传入 cmake.exe 的完整路径。
  • 脚本本身是 run_windows_cuda_tests.ps1，它调用的测试都在同一个目录里，可以直接在站内读。

任何机器 · 不需要 GPU

只查源码契约，不需要 GPU

检查 NCCL 是否完整条件化、MSVC 参数、fmt 补丁、Windows 类型修复、device-link 配置和 wheel 元数据。每一条检查的写法见 test_source_contract.py。

PowerShell，在仓库根目录

.\.venv\Scripts\python.exe -m pytest -ra tests/win_native_cuda_tests/test_source_contract.py

Windows · 已有 DLL

只测已经构建好的 DLL

PowerShell，在仓库根目录，换成 DLL 的实际路径

$env:LIGHTGBM_CUDA_DLL = "D:\path\to\lib_lightgbm.dll" .\.venv\Scripts\python.exe -m pytest -ra tests/win_native_cuda_tests/test_cuda_runtime.py

看 DLL 里的 PTX，在 DLL 所在目录

cuobjdump --all-fatbin --list-ptx .\lib_lightgbm.dll
  • 当前产物应列出 cuda_link.sm_89.ptx 和各个 CUDA 编译单元的 .sm_89.ptx，共 16 项。
  • 不要只用 cuobjdump --list-ptx：它只看最终的 fatbin，在这种构建里会误报 No PTX file found。
  • 测试做了什么，见 test_cuda_runtime.py。

兼容范围

Windows 产物 · sm_89 cubin 加 compute_89 PTX

决定能不能跑的是 GPU 的 Compute Capability 和驱动，不是目标机装了哪个 CUDA Toolkit。nvidia-smi 顶部的 CUDA Version 只表示驱动最高能支持到哪个版本。

  • 已实测

    Compute Capability 8.9

    RTX 40 系列、RTX Ada、L4、L40、L40S。走 sm_89 cubin，驱动理论下限是 R580，实测驱动 610.88。

  • 未实测

    Compute Capability 8.9 以上

    例如 RTX 50 系列。由驱动把 compute_89 PTX 即时编译过去，需要 R595 或更新的驱动，第一次加载会多花编译时间。用之前先在目标卡上跑一遍验证。

  • 不兼容

    Compute Capability 8.9 以下

    RTX 30 系列（sm_86）、A100（sm_80）、Jetson Orin（sm_87）。PTX 只能向更新的架构编译，要另外编译对应的 cubin 或更低版本的 PTX。

  • 会报错

    多 GPU 训练

    Windows 产物是 USE_NCCL=OFF，num_gpu 大于 1 时报错。电脑可以装多张卡，用 gpu_device_id 选一张。

在 Python 里用

Python · Windows 和 Linux 相同

调用方式不变：Python 包装层经 ctypes 调用 C API，再进入 C++ GBDT 和 CUDA Tree Learner。只需要把设备设成 cuda。

scikit-learn 接口也一样，例如 LGBMRegressor(device_type="cuda", gpu_device_id=0)。

改了什么

源码 · 6 项改动

每一项都对应一个构建、运行或交付问题，并由源码或测试固定下来。测试命令见验证。

  • 依赖边界

    NCCL 从 CUDA 必选项改成多卡可选项

    新增 USE_NCCL，按条件查找库、包含头文件、加入源码和链接。单 GPU 只做本卡计算，不再被多卡通信库卡住。

    CMakeLists.txt
  • 编译工具链

    适配 MSVC、NVCC 和自带的 fmt

    MSVC 路径用 /utf-8、/bigobj 和 NOMINMAX，不再传 Unix 专用的 -fPIC、-Wall。fmt 在构建目录里打 UTF-32 补丁，不改第三方源码，版本不符时停止配置。

    WindowsCudaFmtPatch.cmake
  • 二进制链接

    让 Visual Studio 真正执行 CUDA device-link

    打开 separable compilation 和 device-symbol resolution，给最终目标加一个空的 cuda_link.cu 触发链接步骤。CUDA Runtime 选 Shared，与 MSVC 的 /MD 对齐。

    cuda_link.cu
  • 源码兼容

    清理 Windows 64 位类型与宏冲突

    CUDA 可见的数值常量改为 constexpr，用 size_t{1} 保证模板参数同型，kernel 模板参数改名为 USE_NCCL_REDUCTION，避开构建宏。

    test_source_contract.py
  • Python 打包

    把预编译 DLL 封装成 Windows wheel

    按 sysconfig.get_platform() 重标平台，把 Root-Is-Purelib 设为 false 后重新打包；支持 PEP 427 build tag。

    build-python.sh
  • 离线交付

    wheelhouse 和零安装便携包

    离线包先校验 SHA-256 再安装。便携包组合 CPython embeddable、app-local 运行库、隔离启动器和冒烟测试，不改系统 PATH、注册表或用户的 Python。

    windows_cuda_portable

这六个文件可以在这里读，和仓库同一版本：点一行里的文件名切换。要看历史和 blame，用面板里的 GitHub 链接。
